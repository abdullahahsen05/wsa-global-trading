## What the system is
Multi-role trading-operations platform — roles TRADER / PARTNER / ADMIN / SUPER_ADMIN: MT4/MT5 accounts, copy trading, partners (IB), admin, Stripe billing, academy, evaluations (prop challenge), bot marketplace, AI assistant, market terminal.

```
Browser ─ Vercel (Next.js 16: UI + 237 /api route handlers, stateless)
              │ anon+cookies (RLS) / service-role (bypasses RLS)
              ▼
          Supabase: Postgres+RLS · Auth · Realtime · Storage(bot-files, private)
              ▲ service-role
AWS EC2 eu-west-2: wsa-copy-worker · wsa-risk-worker · wsa-background-worker
   (systemd, SAME repo `main`, secrets from SSM /wsa/test/*)  ──▶ API2Trade (mt4api.dev) ──▶ MT4/MT5 brokers
Also: Stripe (checkout + signed webhook), Gemini/OpenAI (server-side), dxFeed (terminal proxy)
```
The copy-trading system "hosted elsewhere" = the three AWS workers. They meet the web app **only through the Supabase database** (tables `copy_*`, `background_jobs`, `trading_accounts`, …).

## Golden rules before a change (§18)
1. **Classify first:** web-only / shared (`src/lib/**` used by the workers) / database / env / infra. *Shared = live on AWS as soon as it pulls `main`.*
2. Worker-loaded modules guard with `if (typeof window !== "undefined") throw …`; do **not** `import "server-only"` there and do not use `next/headers`/React.
3. Idempotency keys are load-bearing (`copy_master_events.dedupe_key`, `copy_trade_links (source_event_id, follower_account_id)`, `trades.external_trade_id`, `background_jobs.unique_key`, `stripe_webhook_events.stripe_event_id`, rebate unique indexes). Never loosen them.
4. Only one path to the broker, behind `executionAvailable()` / `BROKER_EXECUTION_ENABLED`; never fake success when a gate blocks.
5. Service-role code (`createAdminClient`) bypasses RLS: new routes need the right `require*` guard **and** an explicit owner/partner filter; keep the `{ok,data}` / `{ok:false,error}` envelope.
6. DB changes are manual and forward-only (next file `062`; `057` = optional margin columns, `058` = optional chart sampling functions, `059` = optional cash flows + broker web-terminal directory, `060` = optional trade gateway, `061` = optional self-copy activity + strategy-follower calibration - the app must keep working without each of them); DB first, then web, then workers; never drop/rename a column the workers read in the same release.
7. `ENCRYPTION_KEY` must be identical on Vercel, AWS and any local run that shares the DB (it encrypts broker credentials and stored AI keys).
8. React-query keys ↔ `useRealtimeUpdates` are coupled by name; renaming silently stops live updates. (By design `['account-performance', …]` is only invalidated debounced on `trades` events + 60 s polling — never on every snapshot event.)
9. Next.js 16: `src/proxy.ts` (not `middleware.ts`), webpack dev, async `cookies()`/`params`; read `node_modules/next/dist/docs/` before using Next APIs (`AGENTS.md`).
10. **PostgREST returns at most 1000 rows per request** (`.limit(10_000)` does not lift it) and `account_snapshots` gets a row every ~5 s per connected account (~17 k/day). Never read “all snapshots/trades” with one query: sample (`performanceService` probes), page with `.range()`, or aggregate in SQL (`platform_equity_timeline`).
11. **Charts never invent data.** No generated curves, no fallback “bell” shapes; draw recorded snapshots, closed trades and explicitly flagged estimates (`estimated: true`, dotted). Empty = an explicit empty state. A chart ends at the last stored snapshot (workers off ⇒ the line stops there).
12. **Chart window is per account** (`resolveWindow` in `lib/charts/performanceSeries.ts`): live ⇒ ends “now”, no data for > 15 min ⇒ ends at the last data; recording gaps are bridged only with flagged estimates built from closed trades; trade markers ≤ 150. A fixed range (1D … 1Y) always spans the period the person chose, counted back from the window end - never cut at the first data point (the stretch before it is shaded and labelled); only “All” starts at the first data point. Change that logic in `lib/charts/*` / `performanceService`, not in the components. Migration `058` is optional: the service must keep working without it (probe → fall back, remember “missing” for 10 min).
13. **Terminal workspace** (`/api/terminal/workspace`) is owned by that route: `/api/terminal/preferences` must keep merging `layout` and ignoring the `workspace` key. RLS lets users write their own `terminal_user_preferences` row directly, so always pass the document through `sanitizeWorkspace` (document `version` 2: default source `auto`, `brokerTerminals` = one pasted address per broker, ≤ 20, every address re-validated). **Never put a password, token or decrypted value in it.**
14. **MetaTrader pane:** `resolveMetaTraderLaunch` is the only function that returns a full login (one account, always filtered by `user_id`, admins included); the password is never returned or logged; URLs only via `buildMetaTraderUrl` (https only, never this site's own origin); opening an account is audited (`METATRADER_TERMINAL_LAUNCHED`). Keep panes mounted but hidden — unmounting the iframe logs the user out of the terminal. The classic URL (`metatraderweb.app/trade`) is **valid for MT4 only** (MetaQuotes closed the shared MT5 web terminal on 1 Aug 2023): an MT5 account opens in the web terminal its broker hosts, which the default source **Automatic** finds from the account's server (`brokerWebTerminalService`, route `POST /api/terminal/metatrader/resolve`); only if that fails does the user paste an address once per broker. Every address must carry the account's own `servers` / `trade_server` / `login` / `startup_version` and `startup_mode=no_autologin` (otherwise MetaQuotes reconnects to its default MetaQuotes-Demo account; only the user's own "Reconnect automatically" checkbox, `metatrader.autoLogin`, default off, leaves it out); platform = stored value, else inferred from the server name, never guessed; the MetaQuotes-hosted *modern* terminal only knows MetaQuotes-Demo.
15. **TradingView is the free embed widget.** Account login, saved layouts, alerts and account watchlists are impossible inside our page (`frame-ancestors 'none'`, TradingView terms) — do not proxy the site or strip headers; the only real route is TradingView's licensed Advanced Charts / Trading Terminal library. The watchlist in the terminal is stored in WSA. Default chart = dark, UTC, MA 50 + MA 200 (`STD;MA%1Cross`, in_0 50 / in_1 200), no volume (`hide_volume` sent explicitly); options live in `TradingViewOptionsPanel` and the workspace document; send only keys the widget whitelists, `studies` as objects only, never `range`; there is no `calendar` key (the old toggle did nothing and was removed).
16. **Tooling traps:** `src/types/lucide-react.d.ts` is a hand-written ambient module — add every new lucide icon there or `tsc` fails. Vitest only collects `tests/unit/**/*.test.ts` (node environment); component tests use `// @vitest-environment jsdom`, `createElement` (no JSX) and `tests/unit/helpers/reactDom.ts`. ESLint rule `react-hooks/set-state-in-effect` is an **error** (adjust state during render under a condition instead of `setState` in an effect).

17. **Broker order times are never read with `new Date(text)`.** MT4/MT5 send *server time* (UTC+2/+3, DST) as text without a zone; use `lib/broker/orderNormalization.ts` (UTC epochs first, server text converted with the offset learned from the same payload, placeholders and future times dropped, zero-volume balance rows are not trades). Charts sort by the normalised close time.
18. **Partner money rules.** Only the WSA subscription commission (`partner_commissions`, APPROVED → withdrawal allocation → PAID) is withdrawable; broker IB / CPA / Hybrid rows (`partner_rebates`) are *reporting only*. A refund reverses PENDING / unreserved APPROVED commissions (`REVERSED`), never PAID or reserved ones. Rebates: only CONNECTED TRADER / COPY_MASTER accounts and only trades closed *after* `partner_assigned_at`; CPA once per partner / client / broker (checked in code - the DB index ignores a NULL `broker_provider_id`; cancelled rows count as done); every total is computed over **all** rows with `selectAllPages` / `selectAllPagesForIds` (PostgREST 1000-row cap, id lists ≤ 100) - never from "the newest N rows". `partnerRebateCalculationService`, `rebateRules` and `pagedSelect` are shared with the AWS workers: no Next / React / `server-only` imports. Admin CPA tier deposits must ascend (`partnerBrokerConfigurationSchema`).
19. **Account data chain (API2Trade → snapshots / trades → chart), §6.8.** Profit is **net**: `orderNetProfit` = profit + commission + swap (+ fee) - never store or sum gross profit. A broker `AccountSummary` goes through `readAccountFigures` (complete and finite or `IncompleteAccountSummaryError`) before `recordAccountSnapshot`; a bad reading is skipped, never stored as zeros. Trade lookups in the sync are paged (`selectAllPagesForIds`, chunks of 100) and only changed rows are updated - a plain `.select()` over trades silently stops at 1000 rows. One reading per moment: `refreshAccountTrades(…, { snapshot })` reuses the caller's snapshot.
20. **Growth is a time-weighted return, never `value / first value`.** `deriveSeries` chains `(value - flow) / previous` per reading; deposits / withdrawals (`account_cash_flows`, from `extractCashFlows` → `recordCashFlows`, idempotent on `(trading_account_id, external_id)`) are taken out of growth and drawdown; growth starts at 0 % at the first reading. A one-sample jump > 20 % that returns within 8 % is dropped (`dropGlitchSamples`) and counted in `coverage`. Without migration 059 the maths falls back to the old formula and the DTO says `cashFlowsSupported:false`.
21. **Automatic broker web terminal (§6.9).** The platform fetches broker websites by itself, so: the domain comes only from the broker directory (API2Trade `Search`) or brand-bound guesses, **never from a user-typed address** (the resolve route accepts no address); https + public IP + same registrable domain + size / time caps; nothing page-derived goes back to the browser except the chosen URL; ADMIN rows in `broker_web_terminals` are never cached in memory nor overwritten (`url = null` blocks a broker); TTLs found 14 d / not found 6 h / unavailable 2 min; the feature must keep working without migration 059 (memory cache only).
22. **Deep chart history (§6.8).** `lib/broker/historyBackfill.ts` walks the dated order history backwards (90-day windows, `API2TRADE_HISTORY_BACKFILL_DAYS` default 365, a time budget per sync, progress per account in process memory, a finished walk repeats weekly) and `Api2TradeBrokerAdapter.fetchTradeHistory` merges it; any problem means "nothing older", never a failed sync. Backfilled trades can create partner rebates retroactively (only trades closed after `partner_assigned_at` count). Calendar ticks and two-line axis labels live in `lib/charts/performanceSeries.ts` (`timeTicks`, `timeAxisLabels`).
23. **WSA Trade (§6.9).** Routes `/api/terminal/trade/*` are `requireTrader`, always for the caller's OWN account (explicit `user_id` filter, admins included), partners 403. Open needs `executionAvailable()` + an ACTIVE platform subscription (admins exempt) + no risk block (`getRiskEnforcementState().blockedNewTrades`); modify / close are never blocked by risk. Every order carries a `clientRequestId` (repeat protection, in memory of the instance), writes an audit row, and has the comment `WSA Trade` - it must **not** start with `wsa:` (the copy engine's marker). Never read, return or log credentials. API2Trade has no web-terminal link feature; this panel is the answer to "MT5 web terminal without the broker's link". **Since the fifth pass the web tier does not talk to the bridge** (route `gateway`): it checks the gates (ownership, platform subscription, risk for NEW orders only), inserts a `trade_commands` row (unique `(user_id, client_request_id)`, 90 s expiry) and waits for the answer (`lib/gateway/gatewayQueue.ts`); the AWS copy worker's `GatewayWorker` executes it with `executeTradeCommand` behind `executionAvailable()` and publishes `terminal_account_state` / `terminal_account_symbols` for watched accounts. `direct` (the web server itself has the bridge + execution switch) is only a single-box fallback; `WSA_TRADE_ROUTE` pins the route. A command is **never run twice by itself** (expired ⇒ never sent; a RUNNING one whose worker died ⇒ `WORKER_LOST`), the worker re-validates every payload (`parseTradeCommand`), cancel never falls through to closing a position, modify / close / cancel / close-several are never blocked by risk. Without migration 060 the app falls back to `direct` / read-only and says so. Since the sixth pass the panel has no confirmation step and the order path is tuned for milliseconds (rules 30–32).
24. **Copy engine (§9.9).** Never `await` a follower copy, a database round trip or a stream open inside a pump pass (one blocking loop was the main cause of the 2 s+ delay). Every bridge call has a time limit (`requestTimeoutMs`); a timed-out order is never retried automatically (it may have executed). `lib/copy/*`, `api2TradeTransport`, `orderUpdateMessage`, `api2TradeLiveSource`, `copyTradingService`, `supabase/admin` are shared with the AWS workers (no Next / React / `server-only`) and go live when AWS pulls `main`; the new dependency `undici` needs `npm ci` there. Idempotency stays load-bearing (`copy_master_events.dedupe_key`, `copy_trade_links UNIQUE(source_event_id, follower_account_id)`); the CLOSE claim (`OPEN` → `CLOSING`) is one atomic statement; a follower's open-copies counter is counted from `copy_trade_links` and adjusted live. A stream snapshot in which every position vanishes is confirmed by a second read before any CLOSE - do not add automatic missed-CLOSE recovery for strategies without the same safeguard (a wrong snapshot must never mass-close follower trades). `createAdminClient()` is memoised: never sign users in with it. Since the fifth pass the follower pipeline defaults are 48 parallel orders (`WSA_COPY_BROKER_CONCURRENCY`, `WSA_COPY_FOLLOWER_BATCH_SIZE`, was 24) and the idempotency writes stay **database-first on purpose** (event row and link reservation before the order - two Supabase round trips remain on the OPEN path; do not make them fire-and-forget).

25. **Self-copy is never silent (§9.8).** Every (route, position) ends as a `self_copy_events` row - COPIED / SKIPPED / FAILED with a code and a sentence (`selfCopyDecision`); a new gate needs a code, a sentence and a line in "Check route"; activity writes are write-behind (`ActivityLog`) and never awaited on the copy path. The link is reserved before the order; a timed-out order is not re-sent; one chain per source ticket. `copyNewTradesOnly` is literally `true`; `liveSince` is set by the service (create / resume), never by the person; the worker reports `engine_status` / `engine_heartbeat_at` on the route (a report older than 3 minutes = not listening). Everything under `lib/copy/selfCopy*` is shared with the AWS worker (no Next / React / `server-only`).
26. **Calibration `{}` = as before (§9.10).** `CopyCalibration` (`lib/copy/calibration.ts`) is read with `readCalibration`, never trusted raw; strategy followers keep it in `copy_strategy_followers.calibration` (061) - the settings route answers a loud 409 when a non-default calibration is saved while 061 is missing, and the pipeline must work for rows without the column. A reversed trade swaps SL and TP; the follower broker's own symbol spelling is used when its list is known (waited for at most 250 ms); a MODIFY passes `entryPrice: null` (a trailing stop past the entry is valid). `copyExisting` is read by self-copy only.
27. **Connection reuse is for workers only (§9.10).** `databaseFetch` / `warmDatabaseConnections` do nothing until a worker calls `enableApi2TradeConnectionPool()`; never switch the pool on in the web app; `WSA_DB_KEEPALIVE_POOL=false` is the escape hatch; `UV_THREADPOOL_SIZE=16` is set in `wsa-worker-start.sh`.
28. **A local site with the production Supabase keys trades for real (R17).** WSA Trade orders are executed by the live AWS worker, not by the local server, so the `.bat`'s `BROKER_EXECUTION_ENABLED=false` does not protect the account. Tell the owner to test with a demo account (or switch the gateway off on AWS: `WSA_TRADE_GATEWAY_ENABLED=false`, restart the copy unit).
29. **TradingView cannot run the user's own Pine scripts in the embed (§6.9).** Do not promise it and do not guess `PUB;<id>` keys; the honest routes are "Open on TradingView" (symbol + timeframe passed), the licensed Advanced Charts library (JavaScript indicators, own datafeed) or an own chart engine on a broker candle endpoint (not integrated).
30. **WSA Trade is one click, with no Confirm step (sixth pass).** Buy / Sell / Close / Delete and the "close several" chips send at once; the only forms left are the ones that need a number from the person (SL / TP, lots of a part-close, the price of a pending order) and their Save / Close button is the command. Do not bring a confirmation bar back - the owner asked for it to go. What protects the person instead: their own rules (require a stop loss, largest volume - checked before anything is sent), the lock while a request travels (`busyRef`: one request at a time, the buttons are disabled), the repeat protection (`clientRequestId`) and the platform gates. The `confirm` key left the workspace document (`WsaTradeWorkspace`); a stored `confirm` is ignored by `sanitizeWorkspace`. The same order sent again after an answer that never came keeps its `clientRequestId` for 90 s (the server never places it twice); a clean refusal or a changed order gets a new id.
31. **WSA Trade speed - what must stay true (sixth pass, §6.9).** AWS (`gatewayWorker`, `tradeExecutor`): order chains and read chains are separate (a slow read never delays an order, a STATE refresh never queues behind an order); OPEN and CLOSE read nothing first; MODIFY reuses the picture read after the last order if it is ≤ 1.5 s old (`recentPicture`), otherwise it reads; CANCEL and CLOSE_BULK always read fresh (a cancel must never fall through to closing a real position); right after an order the account is re-read at once and then every 350 ms for 4 s (`WSA_TRADE_GATEWAY_HOT_STATE_MS`); the stored answer is written outside the account chain; idle poll 400 ms (`WSA_TRADE_GATEWAY_IDLE_POLL_MS`, was 750); the owner of a watched account is prefetched; reads run 6 at a time (`WSA_TRADE_GATEWAY_READ_CONCURRENCY`). Web (`webTradeService`, `hooks/useWebTrade`): the ACTIVE platform-subscription check is cached 30 s per user (`hasActivePlatformProductSubscription`; tests call `resetWebTradeCaches()`), the gates run in parallel, the audit row is written in `after()`, the five order routes answer a GET warm-up (`useWarmWebTradeRoutes`: once when the panel opens, every 4 min while visible), the state is polled every 400 ms for 3.5 s after an order (`requestFastRefresh`), and the answer is laid over the lists at once for 6 s (`stateOverlay`: only after a successful answer, never invents balance / equity / margin, dropped by a timer). Do not add a database round trip, a broker read or an `await` to the OPEN / CLOSE path without measuring it with the time report (rule 32).
32. **The time report (sixth pass).** `WebTradeTiming` = `queueMs` + `runMs` (+ `readMs`, `sessionMs`, `sendMs`, `attempts`, measured by the adapter as `ExecutionStages` and stored in the command's answer as `CommandTiming`; the worker logs `[trade-gateway] … done in Xms (queue Yms …)`) from AWS, `serverMs` + `waitMs` from the web route, `totalMs` added by `sendWebTrade` in the browser. `timingText` / `timingHeadline` (`lib/trade/webTradeFormat.ts`) turn it into "N ms in total: network · server · queue · broker (read · session · send) · relay" where network = total − server, server = serverMs − waitMs, relay = waitMs − queue − broker. The panel shows the headline next to the result and the parts under it and keeps both in Activity; a `repeated` answer shows no timing. The floor that remains is about 2 × (web ↔ database round trip) + 2 × (AWS ↔ database round trip) + the poll gaps + the broker's own time: keep the **Vercel Function Region next to the Supabase region** (and the AWS box in that region, `[verify]`).
33. **Panel layout (sixth pass).** The panel measures its own room (`ResizeObserver` on its section), takes the zoom from `effectiveZoom` (the person's `wsatrade.zoom` 60–160 %, or the auto-fit `fitZoom`, never below 80 %) and decides with `isWideLayout` (room / zoom ≥ 720 px) whether ticket and lists stand side by side. The zoom is CSS `zoom` on the part under the title bar - the title bar with the − / Auto / + buttons stays unzoomed so it is always in reach. The divider of the split view (`role="separator"` in `TerminalWorkspace`) is pointer-captured and keyboard operable (arrow keys ±2 %), stores `wsatrade.panelShare` (20–60 %, null = the usual 380–440 px column) and drives the grid through the CSS variable `--split-columns`; the pane is `clamp(520px, 80dvh, 1100px)` high (stacked: `clamp(380px, 56dvh, 620px)`). `sanitizeWorkspace` validates both fields; the maths is pure in `lib/trade/panelLayout.ts`.

## Local run (owner clicks `START_WSA_LOCAL.bat`)
Runs `npm run dev -- 3000` (web + API only). It checks `.env.local` by **existence only**, never reads it; forces `WSA_DEV_WORKERS=false`, `BROKER_EXECUTION_ENABLED=false`, `NEXT_PUBLIC_SITE_URL/APP_URL=http://localhost:<port>`, `WEBAUTHN_RP_ID=localhost`. The local site uses whatever Supabase the owner put in `.env.local` — with production keys, local admin actions steer the **live** AWS workers (§16.4). **Since the fifth pass that includes WSA Trade orders: they are executed by the live AWS worker and are real (R17, rule 28).**
**Never run** (against a DB that matters): `npm start`, `npm run test:e2e` (both start the workers), `npm run migrate`, `seed:*`, `scripts/reset-users.ts` (deletes all auth users), `scripts/setup-stripe-products.ts`, `*:worker` scripts, root `sync-*.mjs`, and *Admin → Jobs → run now* from a local instance connected to production (§16.5–16.6).
